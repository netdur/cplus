3. Exceptions and special cases (the interesting part)
3.1 "Explicit return required" — three carve-outs
sema.rs:7609-7692:

A tail whose every path diverges (all-return match/if) skips E0333 and skips type-checking against the declared return (sema.rs:7613-7625).
#[naked] bodies skip both E0333 and the return-type check (sema.rs:7634-7638, :7665).
A unit function whose tail is a unit-typed if/match/block skips E0333 — but a trailing call still errors, deliberately ("foo() and foo(); would otherwise be two spellings of one statement"), sema.rs:7641-7666.
Separately, a value-returning body with no tail and no return is E0306, whose divergence predicate is a different function from lower's, specifically to know that a break-less loop never falls through (sema.rs:20544-20558).

3.2 Blessed-interface / bound admission
satisfies_bound at sema.rs:3698-3757:

Copy → structural is_copy; Send/Sync → structural is_send/is_sync.
Hash, Eq, ToText admit primitives only because a blessed dispatch arm exists; Ord and Clone are deliberately excluded — "admitting them here would create the mirror-image mismatch: a bound that type-checks and a body that cannot call the method" (sema.rs:3726-3733).
Otherwise the bound is satisfied only by a (interface, struct) pair in interface_impls. Enums can never satisfy an interface bound — there's a debug_assert documenting that no (interface, enum) pair can exist (sema.rs:3739-3752), because validate_interface_impls resolves the target through struct_by_name and rejects anything else with E0325 (sema.rs:5068-5080).
3.3 Three different blessed receiver sets that don't agree
sema.rs:13329-13389:

to_text: all ints + f16 f32 f64 + bool + str (:13329).
hash: ints + str only — no bool, no floats ("Bool and floats aren't typical hashmap keys; add if motivated", :13352-13355).
eq: hash set plus bool (:13373-13375). Text deliberately excluded from to_text (:13324-13328).
3.4 Blessed method dispatch (a fixed cascade before nominal lookup)
sema.rs:12695-12935, in order: SIMD/Mask methods → to_text() → to_bits() (floats only) → next() on Iterator[T] → hash() → eq(x) → is_null()/is_not_null() on *T and fn(...) (:12831) → write_zeroed() on *T (:12844) → count()/is_empty() on slice and array (:12867) → the impl str table (:12885).

3.5 The blessed impl str block
sema.rs:4299-4400. Exactly one program-wide (E0385, :4314); everything else is E0386: no impl str: Interface (:4303), no method generics (:4328), no gen/async (:4340), receiver must be plain this — ref this/take this rejected (:4354), no associated fns (:4366), cannot redeclare to_text/hash/eq/drop (:4379). A str method call in a build without stdlib/str is E0324 with a note naming the import (sema.rs:12907-12930), and len/length/size get a "spells it count()" note.

3.6 Marker-impl exceptions
impl X: Copy is rejected — Copy is structural only (E0510, sema.rs:5000-5010).
impl T: Send {} / impl T: Sync {} must have an empty body (E0915, sema.rs:5017-5028); an empty impl of any other interface is E0916 (sema.rs:5043-5054). Conditional form impl Arc[T: Send + Sync]: Send {} records per-param bounds (sema.rs:5029-5041).
Marker blocking: a bare *T stays Send/Sync, but a nominal type that transitively hides a raw pointer is !Send/!Sync (sema.rs:3316-3325, marker_blocked :3336-3390). The #[lang("rc")] and #[lang("mutex_guard")] types block structurally (sema.rs:3392-3400). Keying is on the resolved nominal identity, not the leaf name.
3.7 Literal typing
check_int_lit, sema.rs:10766-10790: unsuffixed integer takes the expected type only if that type is_int(), else falls to Ty::I32. Range check is against the resolved type, with a negated-literal carve-out so -128 is a valid i8 (sema.rs:24985). Character literals lex to Int with a u8 suffix — 'A' is 65u8 (SPEC.md:99-102). f32-suffixed floats are parsed at f32 precision then widened (SPEC.md:96-97). Float over/underflow to ±inf or 0 is a lex error FloatOutOfRange (lexer.rs:279-283).

3.8 Coercions (there are five)
Text → str, at any site with an expected Ty::Str — argument, binding, return, receiver (sema.rs:8237-8250). This is a blanket rule inside check_expr, not per-site.
Text → str in ==/!= when LHS is Text and RHS is str (sema.rs:15838-15855).
string literal → Text — only a literal, and each site decides whether it applies; ref/take parameters are excluded (sema.rs:16110-16126, is_str_lit_to_lang_string). This condition was previously copy-pasted at five sites and one of them (enum payload) rejected valid code — bug-12.
integer literal → expected int type (§3.7); index expressions force Some(Ty::Usize) (sema.rs:9897).
named fn → fn pointer, type-directed at the expected slot (sema.rs:17803-17870); the coerced value takes the expected slot's parameter markers.
3.9 Operator special cases
check_binary, sema.rs:15784-15960:

p + n / p - n on a raw pointer is pointer arithmetic; * and / on pointers stay rejected (:15791-15796).
% on floats is E0316 (:15815-15822).
==/!= on struct types is a hard E0302 ("write your own equality function") — the only exception is Text == str (:15846-15868). impl Eq does not wire up ==.
Ordered comparison on a generic type parameter is E0302 with an explicit "C+ has no operator overloading" message pointing at a.cmp(b) (:15877-15895) — added because monomorphization used to emit icmp slt %Point.
Comparisons are non-chainable — a dedicated ParseErrorKind::NonChainableComparison (parser.rs:20,2896).
Bitwise binds tighter than comparison (parser.rs:2896-2975; SPEC.md:267-269).
3.10 for-loop special cases
check_for, sema.rs:8068-8117: a literal range for x in a..b forces both endpoints and the loop variable to i32 unconditionally (:8079-8090). Any other iterable must unwrap to Iterator[T], else E0312 — so arrays and slices are not iterable with for..in (:8103-8117, documented as a trap at SKILL.md:174-178).

3.11 match special cases
sema.rs:9918-9955: match works on enums only; a non-enum scrutinee is E0341 unless every arm is a literal, in which case lower desugars the whole match into a temp binding + if/else chain before sema (lower.rs:683-830) — sema has an unreachable! for a literal pattern reaching it (sema.rs:10229-10231). Literal patterns in payload position are rejected (E0341, sema.rs:10352-10360, "reports/bug-25"), as are nested variant patterns (sema.rs:10344-10346). A match that binds no name does not consume the scrutinee; Some(_v) does bind (leading _ is privacy, not wildcard) — SKILL.md:415-428.

3.12 Pattern-let restrictions
lower.rs:7-17, 962-1067: E0347 irrefutable if let; E0348 guard-else must diverge; E0349/E0350 complement exhaustiveness/overlap (only when else |Pat| was written); E0351 guard success pattern must bind ≥ 1 value; E0352 multi-binding guard patterns are deferred, i.e. guard let Pair(a, b) = … is rejected. A guard var complement binding stays immutable (SPEC.md:533-537).

3.13 drop is a magic method name
sema.rs:4110-4128: must be exactly fn drop(ref this) — no params, no return (E0338); declaring it sets is_drop which forces non-Copy. An extension (impl in a file other than the type's) may not declare drop (E0389, sema.rs:4098-4108).

3.14 Extensions
plans/ext-extensions.md:40-52: any file may impl a foreign type. First declaration of a name wins program-wide (E0326 for a second, anywhere); cannot override; cannot read _ fields (E0403); cannot extend a generic type (E0387); visible only through direct imports (not transitive). Single-file mode / LSP / cpc graph pass None and the gate is inert — so the LSP sees a different method set than the compiler.

3.15 Other one-offs
Associated-fn paths must be exactly two segments (E0312, sema.rs:14600-14607).
fn main is the one function that keeps an unmangled symbol (resolver.rs:8, :2104-2106).
#println takes exactly one argument of type i32 or str (sema.rs:8433-8456) — not a formatted print despite SPEC's wording.
.to_text() is banned in a #[no_alloc] body (E0901, sema.rs:12713-12722).
Interpolation and .to_text() both require the #[lang("string")] struct to be imported, else E0613 (sema.rs:13307-13320, :12736-12750).
Every ${…} segment must be a blessed-ToText primitive, Text itself, or a user impl X: ToText, else E0612 (sema.rs:13276-13297).
#[no_alloc]/#[no_block] are enforced by hardcoded name lists: ALLOC_BLOCKLIST (sema.rs:19842), LEAF_WHITELIST (:19858), BLOCK_BLOCKLIST (:19988), BLOCK_SAFE_LEAF (:20067).
const initializers must be literals; static additionally accepts array/struct literals (lower.rs:1541, :1608). Const uses are substituted at each site — no const global is emitted.
Array length must be an int literal or a non-negative int const — no arithmetic (E0X36).
import "…" as _; is a discard alias exempt from the duplicate-alias rule (SPEC.md:296-301).
Unary &/&mut parse but are rejected by sema with E0312 "references are not yet supported (Phase 5/6)" (sema.rs:14601).
gen fn / async fn silently rewrite the declared return type to Iterator[T] / Future[T] (sema.rs:4744-4748, :5908-5913) — the signature you read is not the signature you get.

5. Parser quirks and ambiguities
No TODO/FIXME/HACK/XXX/todo!()/unimplemented!() anywhere in cplus-core/src (0 hits, case-insensitive). The quirks are documented in prose instead.

Two context bits, one reset point. ExprCtx { allow_struct_lit, line_sensitive } (parser.rs:69-93). in_delimited resets both (parser.rs:161-180). The comment records a real regression (bug-14): when only line_sensitive was reset, if check(Foo { x: 1 }) and if (Foo { x: 1 }).x == 1 both failed to parse — the latter being the flag's own documented escape hatch.
Whitespace is significant in two places. Token::nl_before (lexer.rs:56-65) drives (a) builder-block modifier lines and (b) the statement-boundary rule.
Statement-boundary rule with backtracking (parse_stmt_expr, parser.rs:2183-2218, "bug-13"): after a leading if/match/{, if the next token has nl_before (or is ;/}) the statement ends; otherwise the parser resets self.pos and re-parses from the top as one expression. Backtracking is asserted safe because "the parser carries no state besides position and these two context flags."
Line-leading ./(/[ terminates a postfix chain inside builder blocks (parser.rs:3168-3185).
Container-with-args is )-then-{ on the same line only (at_container_with_args, parser.rs:3524-3556); name(args) with the block on the next line is a parse error rather than two silent items (previously silent — changelog v0.0.27).
Struct-literal suppression in if/while/for..in/match heads (parser.rs:139-146, :4186); the escape is parentheses.
Overloaded delimiters: [ = generic params, generic args, array type, array literal, index, turbofish ::[; * = multiply, pointer type, deref; & = bitand (binary) vs parse-then-reject (unary); ../... lexed greedily (lexer.rs:257-260).
_ is both the wildcard token and a legal import alias.
Non-chainable comparison is a hard parse error with its own error kind (parser.rs:20-24, 35-40).
Reserved-token rejection is a design feature: try is kept reserved specifically so it "never mis-parses as e.g. a try { ... } struct literal" (parser.rs:4174-4177).

7. Short observations for the review
The exception surface is concentrated in sema.rs, not the grammar. The grammar is genuinely small (~95 node kinds, 47 keywords, one page of EBNF). The special cases are semantic: ~10 blessed method arms, 3 non-identical blessed receiver sets, 5 coercions, 3 carve-outs on the return rule, and 2 marker-inference systems.
Three blessed receiver sets that disagree (to_text ⊃ eq ⊃ hash) is the clearest "rule you must memorize per-method" hazard for an LLM writer.
Ord/Clone bounds are unusable on primitives while Hash/Eq/ToText are — an asymmetry the code comment explicitly acknowledges and chose.
The Text→str coercion is a blanket rule inside check_expr, whereas the mirror "lit"→Text coercion is opt-in per site. That asymmetry is the source of at least one recorded bug (bug-12).
Named args + defaults + bound-method references are the largest single block of sugar and the one furthest from "sugarless"; the design note concedes the tradeoff explicitly.
Extension visibility differs between the compiler and the LSP/graph (plans/ext-extensions.md:47-49) — a tool/compiler divergence in a project whose stated tooling story is "query the graph, not grep."

C+ against its four goals
Verdict: The infrastructure half of "LLM writes, human audits" is further along than any language I can compare it to — an embedded, drift-proof error catalog, cpc explain, cpc skill, a resolved code graph over MCP, NDJSON everywhere. The language half is behind the tooling: the everyday texture of real C+ code (3-level match pyramids, fully-qualified generic patterns, dead None arms, 1 as usize, 56-line import blocks) buries the audit signal in mechanical noise. And a handful of silent semantic divergences — the exact thing an auditor can't see — undercut the audit story more than any missing feature. The good news: most of the highest-leverage fixes are subtractions of noise, not additions of sugar, so they don't compromise the sugarless principle if you state that principle precisely.

If you only did five things:

Let match arms drop the redundant type spelling. The scrutinee's type is known; make Ok(v) / Err(e) / Some(p) legal in pattern position of a match/guard/if-let on a known enum (keep full Option[i32]::Some(v) for construction, where the type genuinely isn't recoverable). This attacks three problems at once: it deletes roughly a third of the characters in functions like fs.cplus's read_to_string, it makes guard let short enough to actually use (the corpus has 3,657 match vs 72 guard let — the flattening tool exists and is unused because one line of it is 90 characters), and it eliminates the #1 LLM failure mode your own SKILL.md documents (models writing bare Some(x)). When the most common model error is the more readable form, adopt that form in the position where it's unambiguous. Framed properly this is not sugar and not "several ways" — it's one way per position: bare variants in patterns, qualified in construction.

Kill the silent debug/release semantic fork. + - * trap in debug and wrap in release (SKILL.md §3). That is the same source having two meanings depending on a build flag — the purest anti-audit property in the language, and unnecessary since +% exists precisely to say "I want wrapping." Trap always (Swift's choice), pay the small release cost or lean on the optimizer. In the same family: integer literals evaluating through i32 before as, and gen fn / async fn silently rewriting the declared return type (sema.rs:4744) — the signature a human reads is not the signature the compiler uses. For an audit-first language, "what you read is what executes" should be a locked principle, and these three violate it.

Make iteration real. for v in arr is rejected; the corpus's single most-repeated shape is the while + at + match Option[*T] + + (1 as usize) block, which appears verbatim in the inbox example, twice in its service, and again in objc/bridge.cplus — complete with a provably-dead None arm the author must write and the auditor must read. Define for x in arr / slices / Vec as a normative §18 desugar to the index loop (borrow semantics stated, no iterator machinery needed). Also propagate expected types across binary operators — this.rendered + 1 where the left side is usize should type the literal; there are 1,705 occurrences of 1 as usize paying that tax today.

Flood the fix-it channel. The Applicability machinery, LSP quick-fix wiring, and JSON schema all exist — and there are exactly 9 suggestion sites for 180 error codes, 2 machine-applicable. Every entry in SKILL.md §14's "recurring traps" list should be a structured fix-it: .unwrap()/.map() → emit the guard let skeleton; &x → delete it; impl X for Y → the colon form; len() → count() (already a note — promote it); missing ctx slot (W0824) already prints the line to add — make it machine-applicable. For an agent loop, a MachineApplicable suggestion converts a full re-reasoning cycle into a string replacement. This is the cheapest quality-per-token improvement available to you.

Make the LLM-facing artifacts executable, and ship them consistently. errors.toml is the single most agent-facing artifact in the project, and its verified = true / repro = "checked" fields are hand-maintained claims — write the verify_errors.py that compiles all 180 examples and asserts each produces its own code (the analog of tools/verify_contract.sh). Then fix the distribution: the Homebrew 0.0.26 binary does not have cpc explain while reporting the same version as the repo build — an agent following SKILL.md's first instruction gets multiple input files not yet supported. Same-version-different-features is the worst possible failure for a language whose pitch is a trustworthy agent loop.

What already delivers — don't touch
Ownership as parameter prefixes. fn append(ref this, take value: T) -> Status tells an auditor everything from the signature, checked call-site-only so it stays modular. This is the language's genuinely novel part and it works.
E0510 raw-pointer accountability (drop frees it or opaque marks it) — a real audit invariant no mainstream language has.
The diagnostic catalog discipline: 180 codes, 100% with example + emit-site, 89% with a named pinning test, zero catalog↔compiler drift, embedded into the binary.
Reserved-and-rejected keywords with targeted hints (mut, unsafe, pub, trait, try…) — you've pre-booked the Rust-trained model's mistakes and turned each into a teaching diagnostic.
The honesty signals: cpc query returning unresolved counts so a zero means "answer complete, no grep fallback" — more tools should copy this.
Named params + defaults. Yes, it's the largest block of sugar, and it's the right call — it's what replaced overloading, and the 24-parameter facet constructors show it carrying whole APIs. (It remains underused in stdlib; finish that pass.)
Restate "sugarless" as the principle you actually enforce
The survey found real sugar: named args (three spellings of one call, as the design note itself concedes), bound method references, five implicit coercions, ten blessed methods, builder blocks. So "sugarless" as an absolute is already false — and that's fine, because the de facto principle in the code is better: no hidden control flow, no redundant spellings, inference only where the answer is recoverable from the immediate context. Codify that in SPEC.md. It cleanly admits recommendation #1 and #3 above, and it cleanly convicts the things that should go:

The Text→str / literal→Text asymmetry: one is a blanket rule in check_expr, the mirror is copy-pasted per-site — which already produced bug-12. Make both single-sourced.
The bound-method-reference convention is the riskiest sugar you have: a two-parameter positional contract (fn(..., *u8) + adjacent defaulted ctx) policed by a five-code family (W0824/W0825, E0822/23/24), where forgetting the ctx slot breaks callers in other files at a site they can't fix. Consider promoting the pair to a first-class handler type — a builtin two-word {fn, ctx} value, still a plain C struct at the ABI, passable by value. That deletes the entire convention and its five diagnostics, and it is more sugarless than today: one thing instead of a two-parameter ritual. (It would also retire the "absent handler compared by name, not null" sentinel smell in facet's props.)
The three blessed receiver sets that disagree (to_text ⊇ eq ⊇ hash, sema.rs:13329) and Ord/Clone bounds being unusable on primitives while Hash/Eq/ToText work — every asymmetry is a rule an LLM must memorize per-method and a hallucination site. Unify the sets; admit Ord/Clone with blessed dispatch or remove them from the marker table. Also: enums can never satisfy an interface bound (impl targets resolve only through struct_by_name, E0325) — either lift it or document it as loudly as the closure ban.
if let: zero occurrences in ~490k lines of corpus. Under "function over syntax," a construct with no organic use is a removal candidate — match and guard let cover it. Smaller surface, smaller SKILL.md, one less choice per site.
Decide the unsafe-marking question once
SPEC says there is no unsafe block because "writing the operation is the marker." The codebase then invented an unenforced house style — wrapping raw ops in bare blocks, { *slot = value; } — which is applied in vec.cplus and skipped in text.cplus:862, arena.cplus:108, agent_gtk.cplus:553. An unenforced audit convention is worse than none: it teaches auditors to trust a marker that means nothing. Either enforce it (a lint: raw deref/store outside a marked context) or delete the style. Independently, build cpc audit: a per-module report of every raw deref, extern call, as *T cast, static mutation, and opaque field — the graph already holds all of it. "Every dangerous op is syntactically visible" becomes "every dangerous op is enumerable," which is what a human auditor actually needs at 490k lines. A linter with levels and recorded suppressions (#[allow(..., reason = "...")]) belongs in the same push; six hardcoded warnings is not an audit story.

Close the specific soundness/consistency holes
bugs/assignment-through-a-raw-pointer-does-not-drop-the-old-value.md — (*p).field = v leaks where h.field = v drops. Two spellings of one assignment with different semantics is exactly the class of bug this language exists to prevent. Fix before features (your own rule).
The str-outlives-Text escape via *u8 erasure (partly open) — you closed the E0516 write-path family; this is the same shape.
Generated appkit.cplus has Button::from_raw not retaining while ButtonCell::from_raw does — a generator inconsistency that turns into a use-after-free audit trap; fix in the bindgen classifier so it can't recur.
ABI lowering is spread across drifting site lists (the effective_move and Win64-byval site counts have both grown since their invariants were recorded). Centralize into one ABI module; the strict-clang-parity testing you already do is the net that makes the refactor safe.
Hygiene that matters more here than in a normal project
Because docs are the LLM's context material, drift is a correctness bug, not a cosmetic one. Found this pass: SPEC advertises cpc run, #print, #[deprecated], #[link(...)] — none exist; SPEC's marker-impl codes (E0860/E0861) don't match the compiler's (E0915/E0916); the SPEC intrinsic and attribute tables omit about a third of what's real; COMPILER.md describes a caret/color renderer that isn't implemented and test counts stale by 2–30×. Add a CI doc-check that greps every code, command, attribute, and intrinsic named in SPEC/SKILL/COMPILER against the source of truth — the same move that made errors.toml drift-proof. While there: renumber the literal-X codes (E0X30, E0X36) before they spread further; run the workspace test suite on push, not only on release tags, and run the vendor cpc test suites in CI at all; and reconcile the LSP/graph seeing a different extension-method set than the compiler — "query the graph, not grep" only holds if the graph never disagrees with cpc build. Finally, examples/ (the code that shows the pleasant face of the language) is written against the old facet API and sits outside all test coverage — the showcase should be the best-tested code you have, not the least.

Two smaller pleasantness items with outsized surface area: an import facade / re-export mechanism (56 consecutive import lines per facet module, with no way for a package to present one front door), and failure detail in cpc test --json (today an agent learns which test failed but not why, where, or with what values — add message and file:line, and consider a blessed assert message form so tests stop encoding "why" in function names).

The one-sentence summary: the tooling already treats the LLM as the author; the next release should treat the human auditor as the reader — strip the mechanical noise (patterns, iteration, literals), make every semantic divergence loud or impossible, and turn the audit conventions into checked, enumerable facts.

================================================================================
TASK LIST — de-drift, error-surface sugar, and the modern-language push
================================================================================

Three principles behind every task below:

P1 — Sugar is not candy. A construct earns its place when it deletes a class of
     generated-code errors or a redundant spelling; it is rejected when it hides
     control flow, allocation, or ownership. "Sugarless" was never the real rule —
     this is.
P2 — The drift rule. An LLM's trained prior (Rust for the language, React/Flutter
     for facet) must either compile correctly or fail with a diagnostic that
     carries the replacement. "Looks the same, behaves differently, says nothing"
     is the only bucket that costs loops — drive it to zero.
P3 — The guardrail ladder. Unrepresentable > compile error with fix > lint > doc.
     Small models fall off the doc rung first (facet "not reactive" proves it);
     promote every known trap at least one rung.

0. DOCTRINE
-------------------------------------------------------------------------------

  with the stated rule of P1, applied as a checklist to every future proposal.
  Every syntax debate becomes a checkable test instead of a taste argument, and
  error-surface sugar gets in without opening the candy door.

- [ ] Run a false-friend census against the drift rule. Enumerate every place C+
  is Rust-shaped-but-different and facet is React-shaped-but-different, and file

- [ ] Rank every SKILL §14 trap on the guardrail ladder and promote each one rung.

  ### new

  1. Structural derive through the empty impl — your own idiom, extended. You already have the perfect mechanism: impl Handle: Send {} where writing the empty impl is the assertion. Extend exactly that to impl Point: Eq {} / Ord / Hash / Clone / ToText — empty body means "compiler, generate the memberwise implementation." Today == on a struct is a hard error telling you to write your own equality function, and user types can't be HashMap keys without hand-rolled boilerplate that models get subtly wrong. This is the single biggest modernity gap: every current language derives these, and C+ can do it with zero macros and zero new syntax.

2. distinct type aliases (newtypes). type UserId = distinct i64 — same representation, same ABI, but not interchangeable with i64 or with ChannelId. It's the cheapest safety feature in modern language design (Odin, Nim, Go's named types), costs nothing at the C boundary, and it's tailor-made for LLM-written code, where mixing up two ids of the same primitive type is a classic silent bug no borrow checker catches.

3. Scoped structured concurrency. A thread::scope-shaped construct where spawned threads are guaranteed joined at scope exit — which means the borrow checker can prove they can't outlive the data they borrow, so threads can share a parent's locals without Arc. Your partition+join idiom is already 90% of the way there; making the scope a checked guarantee instead of a convention is the modern move (this is the direction Swift, Kotlin, and Rust all converged on), and it's the feature that would make C+'s ownership model visibly pay off across threads.

4. Const expressions. Not comptime, not const fn — just folding pure arithmetic over literals and consts, so [u8; CAP * 2] works and big bitmasks don't need the wrap-through-i32 arithmetic dance. const restricted to bare literals is the one place C+ is less capable than C89, and every workaround it forces is a documented footgun.

5. Function contracts: #[requires(...)] / #[ensures(...)]. Debug-checked, release-elided (or kept, your call), and printed in cpc doc and the graph. You already invented the category with #[no_alloc]/#[realtime] — compiler-checked behavioral claims in the signature. Pre/postconditions are the same idea generalized, and they're the most audit-native "modern" feature there is: the LLM states intent machine-checkably, the human reads it in the signature, the harness catches violations. Design-by-contract is having a genuine revival and C+ is unusually well positioned for it.

6. FFI-completeness trio: #[repr(C)] union, packed structs/bitfields, and repr-typed enums. For a language whose identity is "bounded by C ABI," not being able to describe a C union or a bitfield struct means real headers can't be bound without lies. You already reserved the union keyword — this is finishing the boundary, not growing the language.

7. Interface default method bodies. An interface method with a body that implementors can omit — monomorphized like everything else, no dyn involved. It cuts N-copies-of-the-same-method boilerplate (the thing your facet generator exists to paper over) and it's the one trait-system convenience that costs nothing semantically.

8. Typed option-sets. A blessed flags form over an enum (Flags[Dirty] with |, contains) replacing the (dirty & label::P_FONT_SIZE) != (0 as u64) texture that dominates facet_appkit. Set membership spelled as set membership is both more modern and more auditable than mask arithmetic.

9. Range-indexing on slices — xs[a..b] as a checked view. Safe ptr+len views are the modern systems primitive (it's Zig's whole pitch), you already have the slice type and str slicing methods; letting the index syntax produce sub-views generalizes what str.slice(from:to:) does ad hoc.

10. Checked narrowing: as? returning Option. Plain as silently truncates, which sits oddly next to "no implicit conversions." An explicit fallible cast gives models and auditors a way to say "this narrowing can fail and here's the handling" without touching the infallible as for the cases where truncation is intended.

And to be explicit about what I would not add, because "modern" often gets misread as "more Rust": capturing closures (your (fn, ctx) pair — ideally as the first-class handler type — is the honest C-ABI answer), dynamic dispatch / existentials (the no-dyn property is what makes the code graph complete and unresolved: 0 meaningful — that's worth more than trait objects), macros/comptime beyond const expressions, and exceptions in any costume. Those would make C+ more familiar, not more modern.
