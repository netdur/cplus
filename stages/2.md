# Stage 2 — generate the contract

Status: **DONE.** 482 ADOPT rows, 362 declared verbs over 38 generated
controls, 29 enums, ~13.7k generated lines — plus four hand-written
facet-origin controls and two modifiers (see *facet's own words* below).
Gates green: `cpc test` 354 (plain, `--asan`, `--release`), flex_layout 280,
stdlib 290, regeneration byte-idempotent.

Turn the Stage 1 ledger into facet's declared contract. What Stage 2 must
produce was settled from the start; what the emitted code should look like
was not, and the sections below record how it came out.

## What closed it

The generator emitted the contract in `c4a6d9c`, but nothing checked its
output. Three things were wrong and none of them was visible to a test:

- **31 ADOPT rows were discarded in silence** by a `SKIP_TYPES` set, so the
  ledger and the emitted contract disagreed with nobody the wiser.
- **The shared band was 15 of 41 verbs**, missing `native()` — which the
  ledger explicitly adopts as the escape hatch INTENT blesses.
- **The names carried MAUI through**: `set_line_break_mode` against a type
  Stage 1 had already renamed `LineBreak`, `set_is_visible`,
  `set_font_auto_scaling_enabled`.

All three are fixed, and the generator now has Stage 1's discipline: four
guards that exit non-zero and name what they found. A row that nothing
carries, a command that writes a field its control lacks, a shared-band verb
in neither the forward list nor the deferred list, and a name the guideline
rejects each fail the run and write nothing.

## How each row is carried

Every ADOPT row reaching a control lands in exactly one of these, and the
guard fails on a row that lands in none.

| carrier | n | what it is |
|---|---|---|
| prop | 277 | a field, a dirty bit, a setter, a reader |
| event | 58 | a build-time handler: `fn(*u8, *u8)` plus its ctx |
| slot | 16 | a **named child**, not a property — see below |
| shared | 7 | the band on `Node` already answers it |
| command | 6 | a method: a write plus a dirty bit, same shape as a setter |
| owned | 1 | not Copy: written by `take`, read one element at a time |
| skip | 7 | recorded with the reason, in the manifest |

**A subtree is a child, not a property.** MAUI models `Header`, `Footer`,
`EmptyView`, `Content` as bindable properties because binding is how it fills
one. facet describes a tree, so a header IS a child, in a named slot the
parent can replace in place. The slot name lives in its own `Data.slot` field
rather than overwriting `Data.key`, so the application's own key survives and
`find` still reaches the node.

**A command is a setter.** `scroll_to(index:)` writes a field and sets a bit;
`begin_refresh` writes `is_refreshing`. No verb-indexed table, so the backend
seam stays the ~37 apply functions.

**7 rows are still not emitted**, all of them genuinely continuous events
(`observe_scrolled`, `observe_drag_interaction`). An `events::Subscription`
needs the events package, which Stage 3 brings in with the services tier.
They are in the manifest with that reason.

## Language constraints (verified against the compiler)

- No inheritance. `interface View: Element` and `struct Button : View` are
  both E0100. MAUI's hierarchy cannot be transcribed.
- Interfaces are bounds, not types. `fn f(e: Element)` is E0303; a
  heterogeneous `[Element; 2]` is E0303 + E0329. No dyn.
- Therefore the tree is **one concrete type**. `Node` cannot be polymorphic.
- Extensions: any module may add methods to a concrete type it does not
  declare, cross-package, gated on importing that module (E0324 otherwise).
  Generic types are E0387.
- Interface impls verify both ways (E0503 / E0504 / E0505) and are pinned by
  the orphan rule (E0507).
- `-> ref T` does not parse. `Vec` has no borrowing element accessor, so a
  live child cannot be handed back by reference.

## The model, as built

Sketched in `skel.txt` and accepted, with one change.

- **One tree**: `type Node = flex::Node`. facet's per-node data rides in the
  payload slot flex already owns and releases. Geometry is read from flex's
  `frame()`, never copied.
- **Per-widget state** — *not* a tagged union, as the sketch had it. `Data`
  carries a kind tag plus an owned typed pointer, because an enum payload
  cannot be moved out through the raw pointer flex's attachment hands back
  (E0509), and a union would size every node by its largest variant.
- **Two types per control**: a constructor used while describing, and a typed
  non-owning cursor used after mount. A wrong-widget verb is E0324 and a
  wrong-kind lookup is `None`, instead of a silent no-op.
- **One module per control**, gated on import.
- **A row generates members, not registrations**: a field, a constructor
  parameter, a setter, a dirty bit, a line in the backend's apply function.
- **The backend seam is ~37 apply functions**, not 338 registrars.

## The naming pass

The generator transcribed MAUI's member names and never checked its output
against `naming_guideline.md`. The rename table is in `maui_map.RENAME` —
keyed by MAUI member, because the rule is about the word, not the row: wherever
MAUI writes `FontAutoScalingEnabled`, facet writes `font_scales`. 48 rows.

Three rules, all now checkable:

- **Booleans read as assertions, setters do not.** `set_enabled(false)` /
  `is_enabled()`. `set_is_opaque` is the one survivor — `opaque` is a C+
  keyword, so the stem is unspellable, and the exception is recorded in
  `ALLOWED` with that reason.
- **Omit needless words.** `set_horizontal_scroll_bar_visibility` (36) became
  `set_horizontal_scroll_bars` (26), which is now the lint's budget.
- **Name for the role, not the class MAUI wraps.** `set_image_source` →
  `set_image`; `set_line_break_mode` → `set_line_break`, which is what its own
  type has been called since Stage 1.

A fourth defect surfaced once the guards existed: `DISCRETE_EVENT_HINTS` was
missing nine words, so 16 discrete events (`WebView.Navigated`,
`SwipeItem.Invoked`, the `GraphicsView` interactions) became `observe_` rows
that Stage 2 then could not emit at all. The band decides whether a row is a
build-time handler or a subscription, so a missing word there is not cosmetic.

## Open

1. ~~**Child storage.**~~ **RESOLVED** by flex_layout `02666a7` — children
   moved into their own heap slots (`Vec[Box[Node]]`), so every node's address
   is stable from insertion until that node is removed. Sibling appends,
   inserts, removals and `move_child` reorders never move a node, so a `*Node`
   cursor from `child_ptr(at:)` survives tree churn. `Rc[Node]` + `Weak` was
   considered and ruled out: `Rc::with_mut` refuses while any `Weak` exists,
   which a tree the engine mutates every pass cannot live with.

   The tree also gained the structural verbs facet needs, all of them
   invalidating the incremental cache: `insert_child(node, at:)`,
   `remove_child(at:) -> Option[Node]` (detach and return the subtree —
   reinsert to reparent), `move_child(from:, to:)`, `child_index(of: *Node)`.
   `add_child` now returns `Status`, and the raw children vector is private;
   traversal goes through `child_ptr`. 265 tests green.

   The residual — a cursor held across the removal of its own node or an
   ancestor — is closed by `9535950`: `removal_count()` is a process-wide
   monotonic counter bumped only by successful `remove_child`. A holder
   captures it alongside the cursor; while it is unchanged, no node anywhere
   has died, so the cursor is provably live **without dereferencing it**.
   Changed means re-derive by key. Moves, inserts and failed removes never
   bump. The only false positive is an unrelated removal, which errs safe.
   This buys a generation tag's safety without memory outliving the node,
   which is what made an arena fight the by-value builder model. 271 tests.

   So facet's cursors carry `{ _p, _seen }`, not a bare pointer.

   Remaining limit: whole-tree teardown is invisible to the counter (it counts
   `remove_child`, not drops), so a cursor must not outlive its tree.

   Settled at the same time: **no parent pointers**. Roots are values the app
   moves and `remove_child` returns a subtree by value, so a stored `_parent`
   would dangle on exactly those two operations. Frames are absolute, so
   nothing in the engine climbs; a holder that needs the parent captures it on
   the downward walk and uses `parent.child_index(of: node)`.
2. ~~**The 41 shared verbs**~~ **RESOLVED.** Generated onto all 38, as
   one-line forwards over verbs that live once on `Node`. No `LiveElement`
   type: a second element type is the generic handle under another name, and
   the whole point of the typed cursor is that there isn't one. 36 of the 41
   are forwarded; the 5 that are not are the shared-band events, recorded in
   `DEFERRED_SHARED` with the reason (they are Stage 3's lifecycle tier, and
   `observe_size` needs the events package).
3. ~~**Reads the platform learns first**~~ **RESOLVED for the shared band.**
   `Data` carries `is_focused` / `is_attached` / `window`, and
   `facet::set_focused` / `set_attached` / `set_window` / `set_native` are the
   write path in. Per-control platform reads (`is_pressed`, typed text) are
   ordinary props; the backend writes them the same way, through the props
   pointer it already holds.
4. ~~**Ordering with Stage 3.**~~ **RESOLVED.** Stage 2 generates the enums
   and the value types, and everything it emits compiles today against
   flex_layout and stdlib alone. Stage 3 does not have to come first.
5. ~~**17 of the 30 enums have no members**~~ **RESOLVED** — the Core
   PublicAPI was fetched, so 25 of the 29 enums read their members straight
   out of a manifest. Four are authored by hand in `HAND_ENUMS` and say so in
   the generated file: `Appearance`, `Keyboard`, `SafeArea`, `ContentLayout`.
   Seven more have only two members, which is correct rather than thin —
   `ClearButton`, `TextFormat`, `Separator`, `AutoSize`, `ItemSizing`,
   `DotShape` and `Buttons` are all genuinely two-valued.
6. **Chained build modifiers.** iris writes
   `facet::label("x").foreground_color(c).font(13.0)`; facet writes
   `label::label("x", text_color: c, font_size: 13.0)`. The live side already
   chains, because every setter returns the cursor. Whether the build side
   also offers the chained form is open, and it is a decision, not a gap.
7. **`key` storage.** `Data.key` is `str`, sound only for literals. Interning
   would make it sound for computed keys and turn `find`'s comparison into a
   pointer compare. Not built.

## facet's own words

Eleven words iris reaches for that MAUI never had. Worked through on
2026-08-03; every one recorded in `maui_map.FACET_ORIGIN` with its reasoning.
Four became modules, two became modifiers, three folded away.

The two rules that fell out, and that a twelfth word should follow:

- **A behaviour that draws nothing is a modifier, not a control.**
  `.gesture(…)` and `.window_drag()` add no node and no native view; they say
  what pointer input on a region means. Making either a control would have put
  a view in the tree whose only job was to hold a callback — and making
  gestures constructor parameters would have put 21 handlers on all 38
  constructors for something most of them never use.
- **An arrangement of existing words is a component, not a word.** `composer`
  is `text_area` + `bordered` + a background. `wrap_label` is `label` with
  `line_break: WordWrap`; it was ever a separate kind only because AppKit has
  a second NSTextField factory, and which factory to call is the backend's
  sentence.

Facet-origin controls take kind tags from **1000 up**, so regenerating the 38
MAUI-derived modules can never collide with one facet declared for itself.

## The gate

```
python3 tools/maui_map.py        # the ledger; fails on an unbucketed row
python3 tools/gen_contract.py    # the contract; fails on any of four guards
cd vendor/facet && cpc test && cpc test --asan && cpc test --release
```

`test_main.cplus` imports all 38 control modules. It did not before, so 32 of
them were emitted and never compiled — which is how a control could carry a
verb that collided with the shared band and nothing noticed.

## Not carried forward

`tools/gen_contract.py` as written does not run: it reads `UNSUPPORTED` and
`KEEP-FACET` statuses that Stage 1 removed. It is replaced, not repaired.
