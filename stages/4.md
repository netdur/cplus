# Stage 4 — facet_appkit: the contract on a Mac

Status: **planned 2026-08-04.** The previous stub here ("tests, standalone
— null renderer, headless suite") was absorbed by Stage 3: the fake
renderer/scheduler ARE the null backend, and the 433-test suite is the
headless gate every change already passes. This page replaces it with the
stage the project actually needs next.

INTENT.md is the judge: facet_appkit reads facet's contract and implements
it with AppKit — or states plainly that AppKit cannot. Nothing in the
backend that the contract did not ask for.

## What Stage 3 left ready

- **The install contract** (handoff records it): five structs + two slots.
  A backend fills `Renderer`, `Scheduler`, `KeyReader`, `SenderReaders`,
  `AgentHooks`, plus `theme::set_is_dark_fn` / `set_theme_changed_fn`.
  Zero fields keep the portable no-op. There is no other registrar; a hook
  family outside these is drift.
- **The conformance harness**: the fake renderer/scheduler tests exercise
  mount, sync, batching, lifecycle, set_content (including native removal
  via `Renderer.remove`), switch_to parking, and job settling. A backend
  that fills the same structs inherits a proven pipeline.
- **The ownership model**: process → Application (`app::current()`) →
  Window (plural) → node. `App::run` makes its record current; windows
  open/close through the application record.
- **The debt ledger**: guard 5b holds 58 tier rows deferred to THIS stage,
  each with a reason (window sizing/policy, density, modal stack, toolbar
  tier, TitleBar content, safe area, soft input). Each either lands here
  or its disposition becomes "AppKit cannot", recorded in the backend's
  manifest per INTENT.

Reference material (the copy-paste rule applies): the pre-regen macOS
facade `git show eb5b1b7:vendor/facet/src/runtime_macos.cplus` (748 lines —
window creation from Chrome, the App loop over nav intents, push/pop,
dialogs, focus observers), `vendor/appkit` (bindgen; hand additions go to
appkit_ext), `agent_appkit`, and the old `agent.cplus`
(`git show eb5b1b7:vendor/facet/src/agent.cplus`). `vendor/facet_appkit`
is an empty scaffold today; `vendor/facet_gtk` still speaks the OLD
per-kind renderer and is out of scope for this stage.

## The work, in order

1. **The window shell.** `runtime_macos.cplus` shadows the neutral facade:
   NSApplication + one NSWindow built from `Chrome` (title, size, min,
   `bar: Bar`, `close_button_only`, zoom), the root mounted into the
   content view, `App::run` looping on nav intents (`go`/`quit` unwind,
   `push`/`pop` secondary windows — port the old loop). Wire
   `app::make_current`, `open_window`/`close_window` to real windows.
   Exit criterion: an empty keyed column on screen, loudly no-op'ing
   nothing.
2. **A walking skeleton of `create`/`apply`.** Six kinds first — label,
   button, text_field, scroll, image, and the keyed-container backing —
   dispatching on `Data.kind` inside the backend, reading props whole at
   create and dirty bits at apply. The shared band (opacity, background,
   enabled, visible, transforms) applies once, on the view, for every
   kind. Then the sweep to all 42. Exit criterion: a real form edits and
   clicks.
3. **Scheduler.** `run_on_main` (dispatch to main), `after`/`cancel_after`
   (NSTimer or dispatch_after with token), `observe_size`/cancel (frame
   observation on the node's view). The sync tick: `Renderer.schedule`
   coalesces into ONE `mount::sync()` per run-loop turn — proposal: a
   CFRunLoopObserver before-waiting, which is exactly M5's "backend
   coalesces" contract. Jobs: the facade's teardown drains the loop until
   `services::jobs_settled()` before dropping screens — the contract the
   review fix defined.
4. **Input.** `KeyReader` over NSEvent (code/chars/modifiers/named — the
   named-key table exists); the gesture band wired through recognizers
   with the decline-chain rule (handler false → next native responder);
   `SenderReaders` (key_of via the accessibilityIdentifier walk — one
   token, three jobs: find key, agent id, a11y id).
5. **The 58 deferred rows, row by row.** Window sizing/policy
   (maximizable/minimizable/max size), IsActivated, window SizeChanged,
   DisplayDensity via backingScaleFactor, UserAppTheme (NSApp appearance
   override), TitleBar content and the Toolbar tier (NSToolbar) behind
   `Bar::Custom`, modal-stack observers behind push/pop. Each flips its
   guard-5b disposition to "implemented" — the guard is the tracker — or
   becomes a recorded "AppKit cannot" in the backend manifest. Mobile-only
   rows (soft input, back button) stay deferred with that reason.
6. **The agent surface returns.** Port `agent.cplus` (install_agent is
   waiting); agent_appkit's Surface re-applied every mount (the compat
   rule already in the notes). The rule that cost a revert stands: an
   agent has no hands — a gesture-only affordance gets a click path in
   the UI, never a new agent verb.
7. **Examples revived.** hello_facet (or a fresh examples/hello_appkit)
   moved to the new API as the visual proof — @ui-authored, themed, keyed.
   Gesture/feel items end with "run it and try" per the standing rule;
   an agent cannot assert drag feel. iris migration is NOT this stage.

## Decisions — resolved with the user, 2026-08-04

1. **The sync tick uses AppKit's OWN loop**: a CFRunLoopObserver at
   before-waiting — the same flush point Core Animation commits on. No
   facet loop exists; the observer is the platform-native coalescer.
2. **The 58 rows: implement everything AppKit can do** during the sweep;
   the mobile-only handful (soft-input policy, nav-bar back button) are
   recorded "AppKit cannot (mobile concept)" in facet_appkit's manifest —
   the same INTENT doctrine as an UNSUPPORTED control verb. No third
   bucket.
3. **`find` is the DOM rule** (implemented in facet immediately): bare
   `find(key)` searches the running app's windows in OPEN order, first
   match wins — like getElementById; `within:` scopes a subtree or
   disambiguates a duplicated key across windows. `mounted_root()` stays
   for facades that want "the active window", but find no longer uses it.
