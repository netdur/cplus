# facet contract ↔ facet_appkit gap audit — 2026-08-05

What the MAUI-bootstrapped contract **declares**, what `facet_appkit`
**implements**, and where the answers are incomplete even when the
coverage gate is green.

**Headline.** Below the kind level, the debt number is zero:

```

  285 live · 23 host-rendered · 5 derived · 4 modifier · 7 create-only
    0 decided · 0 no-carrier · 0 absent

 81 declared handlers
  81 wired · 0 never-fire

 82 tier rows (guard 5b)
  61 implemented · 21 decided · 0 deferred
```

**Updated 2026-08-05 after acting on this report.** Every P1, P2 and P3
item below is now closed; each carries the commit that did it. The tier
ledger's deferred column is empty, `is_secure` is live, and building the
example found three real bugs — the largest being that a DSL-authored
screen reached the window with nothing in it.

`python3 tools/verb_coverage.py --check` passes. Every declared verb has
an answer. That is not the same as every verb doing what a portable app
author would expect on a Mac — the rest of this report is that second

## 1. What the contract is

facet's portable surface is bootstrapped from MAUI's PublicAPI (Controls
+ Core + Graphics), curated by Stage 1 into **ADOPT / DROP only** (no
FUTURE parking), then generated by Stage 2 into one module per control.

| Layer | Count | Notes |
|---|---|---|
| Generated controls | 38 | `props::K_*` 1–38 — button, label, text_field, … |
| Hand-written (facet-origin) | 4 | `symbol` 1000, `tree` 1001, `split` 1002, `window_buttons` 1003 |
| Bare container | 1 | `K_NODE` 0 — flex column/row/etc. |
| Declared prop/command bits | 324 | per-control dirty-bit space |
| Declared handlers | 81 | ride shared `C_HANDLERS` |
| Shared band on every cursor | 79 verbs | opacity, paint, transform, geometry, lifecycle |
| MAUI map | 873 rows | 496 ADOPT; 377 DROP (ENGINE 235, MODEL 86, LAYOUT 56) |

Manifest of every word: `vendor/facet/docs/contract.md`.

## 3. What is still missing or weak

### 3a. Create-only (7) — live flip needs a different object

Listed in `MANIFEST.md`'s `create-only` ledger. A later write does not
reach the screen:

| Verb | Why |
|---|---|
| ~~`text_field.is_secure`~~ | **now live** (`287ab8e`) — `views::reclass` builds the other class and puts it in the slot the old one held. A different object turned out to be a cost, not a wall. |
| `list.row_height` / `tree.row_height` | read when the data source / outline is built |
| `toolbar_item.placement` / `priority` / `is_destructive` | NSToolbarItem built once when the window opens; toolbar draws the label (no attributed destructive style) |
| `menu.priority` | NSMenu built once with the window |
| `window_chrome.spacing` | traffic lights laid out once by the window |

**The remaining seven earn their place on a narrower claim** than the
ledger used to make. It is not "a live flip needs a different object" —
`is_secure` proved that is buildable. It is that the object which would
have to be rebuilt is **not the control's own view**: a row height belongs
to a data source that has already vended rows, and a toolbar item and a
menu belong to the window, which would have to be torn down and reopened.

**Gap for apps:** toolbar item placement and menu priority are fixed once
the window opens.

### 3b. Platform substitutes — implemented, but not the MAUI gesture

These verbs are **live** and handlers **fire**, under a different
interaction model:

| Contract | What MAUI means | What AppKit does |
|---|---|---|
| `refreshable` | pull-to-refresh on scroll | overlaid refresh **button**; sets `is_refreshing`, fires `on_refreshing` |
| `swipeable` + `swipe_item` | swipe-to-reveal actions | right-click / control-click **menu** of swipe items + optional trackpad drag strip |
| `tabs` | native tab chrome | facet row of buttons in the node's padding; panes via `display: none` (NSTabView fought flex layout) |
| `date_picker` / `time_picker` `format:` | format **string** (order + separators) | element **mask** from which components the string names; order/separators stay locale |
| `date_picker.is_open` | open the picker UI | graphical picker in an NSPopover |
| `corner_radius` (4 corners) | per-corner radii | Core Animation: **max of the four** |
| `keyboard` / `return_key` / `predicts_text` | soft-keyboard layout and Return label | hardware keyboard world: field-editor flags / next-field behaviour where they map; soft-keyboard layout has no home |
| `font_scales` | Dynamic Type per control | base size × system preference multiplier where available |

MANIFEST prose in places still reads as if some of these are pure
"AppKit cannot"; the code and the coverage tool treat them as live.
Trust the tool + the apply bodies over the older narrative sections.

### 3c. Sequence controls — shape limits (performance / columns)

| Kind | Implementation | Real limit |
|---|---|---|
| `list` | recycling NSTableView | single column; good for large N |
| `tree` | recycling outline | good for large N |
| `collection` | **materialises every row** as ordinary children | fine for dozens/hundreds; not 10k rows |
| `table` | sequence host + `TableStyle` / row height / uneven rows | **not** multi-column sortable spreadsheet; MAUI `TableView` here is settings-style sections, and the contract only declares 4 verbs |
| `carousel` | paged scroll | `wraps` is a modifier (out-of-range is error vs page); infinite wrap is not a half-built paging model |

Dead-ish path: `controls.cplus` still has `create_list` / `materialise_list`
/ `apply_list`, but `views.cplus` routes `K_LIST` to the recycler. The
materialising path is the collection/table family, not the live list.

### 3d. Contract-side holes (not facet_appkit's to invent)

Stage 4 closed the tier ledger at **57 implemented / 20 decided / 5
deferred**, and those counts still hold. The authority is guard 5b —
`TIER_ROWS` in `tools/gen_contract.py` — not the prose in `stages/4.md`,
which has drifted. Read off the guard, the five deferred rows are:

| Deferred | Why backend cannot finish it |
|---|---|
| `Page.ContainerArea` / `Page.IgnoresContainerArea` / `ContentPage.SafeAreaEdges` | `vocab::SafeArea` exists; only `scroll` takes one |
| `Page.BackgroundImageSource` | shared band has Color/Brush, not image |
| `Page.IconImageSource` | no carrier; macOS window icon is document-proxy, not arbitrary image |

So the five rows reduce to **two carriers worth building** (a page safe
area, a page background image) and one that is arguably decided rather
than deferred (`IconImageSource` — the platform reason is already
written next to it).

**Two rows `stages/4.md` still lists as deferred are not.** They were
closed after that note was last edited, and repeating them is the single
biggest error the stage prose carries:

| Listed as deferred | Actually |
|---|---|
| `TitleBar.LeadingContent` / `TrailingContent` / `Window.TitleBar` | **implemented** — `window_chrome::titlebar_leading` / `_trailing` are subtrees under a reserved `@` key, lifted into `NSTitlebarAccessoryViewController` (`window.cplus:804-833`, commit `ce765c5`, test at `test_main.cplus:2702`). `Chrome` stayed a value struct; the subtree rides a key instead. |
| `ModalPushing` / `ModalPopping` / `Page.NavigatingFrom` | **not deferred debt.** `ModalPopping` and `PopCanceled` are implemented via `should_close`; `ModalPushing` and `NavigatingFrom` are recorded **cannot** — the application initiates every push and route change facet has, so there is nothing to observe that the caller does not already know. |

Also from the contract manifest itself:

| Item | Note |
|---|---|
| `observe_size` | not a cursor method; lives as `services::observe_size(n, cb, ctx:) -> Cancellable` (backend-hook shape) |

**Mobile-only decided** (toolbar back button, soft-input hide, page
busy, drawer toggle): recorded as platform-cannot at the tier level;
not control-verb debt.

### 3e. Drawing vocabulary — closed for canvas, one deliberate omission

`Drawable` is `fn(*u8, *Canvas, Rect)` with a full recorded-command
canvas. Backend replays into `drawRect:`.

| Intentionally not MAUI-complete | Reason |
|---|---|
| `ICanvas.GetStringSize` | needs a live platform context at record time; none exists while recording |
| `draw_text(at:)` y meaning | top-left (facet), not baseline (MAUI) — deliberate contract consistency |

### 3f. Stage 4 item 7 — CLOSED, and it paid for itself

`examples/hello_appkit` is built: one screen, one file, @ui-authored,
themed, keyed, static-free, with the agent surface wired so it can be
driven without a person at the keyboard.

Writing it found three bugs no suite was catching (fixed in `6cf5fca`),
and the first is the reason this item was worth more than documentation:

| Bug | Why every suite was green |
|---|---|
| **A DSL-authored screen reached the window EMPTY** | `@ui { }` is a keyless container; `wants_view` gives it no view by design; `open_window` inserted only the root's own view, so a pass-through root left its children inserted nowhere. The framework's own `open_window` test uses a **keyed** column, which is backed. |
| A focused field lost its text across an `is_secure` flip | the write-back could fire from the old field leaving the hierarchy or the new empty one entering it, either overwriting the props |
| A reclassed view lost its a11y id and intrinsic-size measure | the replacement was built by the kind builder, not by `views::create` |

The first affects **every application that authors its screen the way
the contract asks**. None of the three is visible in a screenshot, which
is the argument for an example that carries an agent surface rather than
only eyes.

## 5. What is *not* a gap (intentionally dropped from MAUI)

Stage 1 DROPped 377 rows. Absence from the contract is deliberate:

| DROP class | Examples | Why |
|---|---|---|
| MODEL (MVVM) | Command, Behaviors, Triggers, DataTemplate, SelectedItem as object, ItemsSource binding | facet is keyed-direct + fn+ctx, not bindings |
| LAYOUT | padding/margin/align on many types, SafeArea on Border | flex_layout owns layout |
| ENGINE | MapText, SendClicked, ArrangeOverride, VisibleViews, handler plumbing | framework internals |

So "MAUI has X and facet doesn't" is often correct and intended. Check
`plans/facet/maui-spec-report.md` and the map before treating absence as
debt.

MAUI types **not** in the facet control set (by design of this seed):
Shell, NavigationPage, FlyoutPage, ContentView-as-template, BoxView's
peers that are pure layout, etc. Promotion is a Stage 1 map decision,
not a backend task.

## 6. Recommendations (priority)

### P0 — none for "verb missing"

No undeclared-or-unanswered control verb blocks a backend install. The
gate is green.

### P1 — contract carriers — **CLOSED 2026-08-05**

Guard 5b now reads **61 implemented / 21 decided / 0 deferred**. The debt
ledger is empty. The five rows all had one cause — facet had never
declared a carrier — and four of them wanted only two:

1. **`safe_area` on the shared band.** `vocab::SafeArea` was declared in
   Stage 2 and only `scroll` could take one. It is on every node now, so
   the node that has to answer the question can be the one that does.
   AppKit will not apply it for us — a content view knows its own
   `safeAreaInsets`, but facet places children by frame rather than by
   constraint, so nothing consulted them. The window's layout pass does:
   the root lays out inside the insets and sits at their origin.
   Closes `Page.ContainerArea`, `Page.IgnoresContainerArea`,
   `ContentPage.SafeAreaEdges`.
2. **`background_image` on the shared band.** The third background thing
   after a Color and a Brush. It rides `C_BACKGROUND` rather than taking a
   bit — "what is behind this node" is one question — and it is the
   layer's `contents`, never a subview, because a subview would be a child
   facet did not put in the tree and every index below it would shift.
   Closes `Page.BackgroundImageSource`.
3. **`Page.IconImageSource` → decided.** A macOS window icon is the
   document-proxy icon of a file (the window's `representedURL`), so a
   verb taking a picture would describe something the platform cannot
   show. Recorded as `cannot` with that reason rather than carried as debt.

The shared band had exactly one free bit of its sixteen; `safe_area` took
it, and `background_image` needed none.

### P2 — quality / scale — **all three resolved 2026-08-05**

1. ~~**collection** recycling~~ — **documented, not built, and the old
   reason was wrong.** It is not the grid: the recycler already models
   grouped sequences. It is `CanReorderItems` — a collection's reorder is
   a drag ending in `mount::remove_child` / `insert_child` on its own
   children, and a recycling collection has no persistent child to move.
   Recycling it is a redesign of `reorder`, not a change of host, so it
   wants a consumer with a long collection AND reordering first. Size
   limit written down: hundreds fine, ten thousand is `list` (`585f643`).
2. ~~Live flip for `text_field.is_secure`~~ — **built** (`287ab8e`).
   `views::reclass` builds the other class, puts it in the slot the old
   one held, carries focus across, and re-applies through `create`.
   Coverage moved 284→285 live, 8→7 create-only. Two follow-on bugs
   found by the example and fixed in `6cf5fca` — see §3f.
3. ~~Multi-column table~~ — **recorded as a contract decision, not debt.**
   The contract declares four verbs for `table` and none is a column;
   columns would have to be invented in Stage 1's map first (`585f643`).

### P3 — hygiene — **all three DONE 2026-08-05**

1. ~~Refresh MANIFEST prose~~ — the touch-gesture section said
   `refreshable` / `swipeable` were unimplemented and got "a plain
   backing view"; both are live. Rewritten (`6725d8c`).
2. ~~Delete dead `create_list` / `materialise_list`~~ — they had zero
   callers; deleted, `fill_rows` kept for collection (`6725d8c`).
3. ~~Stage 4 item 7~~ — `examples/hello_appkit` built and driven; see
   §3f for the three bugs it found (`6cf5fca`).

## 8. Bottom line

| Question | Answer |
|---|---|
| Is the contract missing controls that MAUI seeded as ADOPT? | **No** — Stage 2 guards + iris gap pass closed the silent skips. |
| Is facet_appkit missing create/apply for a declared kind? | **No** — 42/42. |

window chrome): **the contract is there and AppKit implements it.** The
remaining work is carriers, scale, and honesty about Mac-shaped
substitutes — not a missing Button or TextField.
